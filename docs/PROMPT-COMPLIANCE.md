# Prompt compliance audit

Two prompts describe this project — one for a Unity/C# build (`App/`), one for a browser build
(`Web/`). This document checks both, requirement by requirement, and records what was missing.

**How to read it.** A requirement is marked ✅ only when something _verifies_ it: a test, a browser
run, or a file you can open. ⚠️ means present but partial, or present and unverified. ❌ means
genuinely absent. The distinction between ⚠️ and ❌ is the whole point of the document — the two
words "not implemented" and "not proved" are not the same claim, and conflating them is how a
project ends up describing a feature it does not have.

compile and pass their EditMode suite — and that nothing has been run as a game. Unity 6000.6.5f1
imports the project, compiles its 242 scripts with no compiler errors or warnings, and runs the
EditMode suite to a green 64/64 (gearbox, brakes, save system, input map, challenge rules). Every row
below is still ⚠️ or ❌ for the other two reasons: there is no committed content, and no player build
has ever been produced, so nothing exercises the application layer inside a scene.

### Bugs this pass found and fixed

Found by the new tests and the browser run, not by inspection:

1. **A junction was reported metres from the real crossing.** Intersections were detected as "the
   closest pair of sampled points", so on a road sampled every 4 m a traffic light could land in the
   middle of the carriageway. Replaced with exact segment-to-segment intersection.
2. **Clear weather was dimming the sky by 10%.** The sky-top factor had an unconditional 0.9
   multiplier, so "clear" was not the identity case. Found by asserting that clear weather leaves the
   daylight state alone.
3. **Stars were leaking through overcast skies.** Star visibility was derived from the brightness
   factor rather than stated explicitly; it is now a per-profile value.
4. **A long frame made dust fall instead of rise.** Euler integration with an unbounded step let
   gravity overwhelm the upward velocity on any frame hitch. Integration is now sub-stepped and
   capped, which also makes the pool survive a tab restore.
5. **A save notification permanently replaced the main-menu status line.** Pre-existing, surfaced by
   the browser suite once boot timing shifted: the 800 ms save debounce fired after the menu
   appeared, and "Progress saved" hid "Alpine Valley loaded" for the rest of the session. The status
   line now restores its persistent message.
6. **Every dirt road was coloured as asphalt on both maps.** `RoadNetwork.minimapRoads()` omitted the
   `surface` field that both the minimap and the new world map read, so `surface === 'dirt'` was
   never true.
7. **Two challenge tests asserted the wrong shape of the world** — they pinned the challenge count
   and only checked that an unlock existed, not that it was unique. Strengthened rather than relaxed:
   the count is asserted exactly, reward-less challenges must be named explicitly, and each gated
   vehicle must be unlocked by exactly one challenge.
8. **The bridge scorer rejected every bridge on every road.** A bridge was judged by the _worst_
   point in its window, and a window's ends are by definition where the road is back on the ground,
   so the score was always about zero. Both structure types are now judged by their deepest point,
   and the span is what has to clear — which is what "is there a gap worth bridging" actually means.
9. **A span could grow outside the stretch of road its alignment covered.** The clearance was
   measured against a straight line drawn over the search window, but only the window's road was
   straightened: past its end the road reverted to its graded self, free to poke into the hill it was
   supposed to run through. The walk is now bounded by the window.
10. **The tunnel profile's clearance was tested against the wrong side of the road.** Reading the
    terrain's height minus the road's as "clearance" for a bridge inverted the sign of the whole
    test, so a bridge that was buried under twenty metres of hillside scored as an excellent bridge.
    Found by a probe that printed the road height and the ground height at the worst sample.
11. **A structure was placed in the corner of a road.** `windowAt` silently shortened a window that
    ran off the end of the road, and a shortened window covers only the _higher_ ground near that
    end — so it won the mean-fit comparison that chooses where the structure goes, for the wrong
    reason. Windows that cannot fit are now refused rather than clipped. Found while testing the
    window widening added in this pass, which kept re-selecting a corner window.
12. **A jump ramp was swallowed by the hill it stood on.** A ramp is rigid and the ground is not:
    placed pointing along the road without regard for the ground, an uphill-facing ramp is buried,
    because the terrain climbs faster than the ramp's own incline does. Rays dropped on the middle of
    the ramp landed on sand. The ramp now faces down the local grade, so its incline stays proud of
    the ground for its whole run.
13. **The browser suite assumed a structure group contains only meshes.** Adding real tunnel lights
    broke scenario 14 with `Cannot read properties of undefined (reading 'index')` — it was mapping
    `geometry.index` over every child. The assertion now filters to meshes and separately counts the
    lights, which is the state it should have been asserting in the first place.
